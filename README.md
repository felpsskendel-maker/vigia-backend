## Principal mudança

O produto principal **não precisa ser Mercado Livre**.

O backend agora lê as ofertas que a extensão já encontrou dentro de:

```text
dados → comparações
```

e monitora, na nuvem, as URLs suportadas.

Nesta primeira etapa:

```text
Mercado Livre ✅
KaBuM          ✅
Amazon         ainda não
Magalu         ainda não
Shopee         ainda não
```

Exemplo com o PS5 já cadastrado:

```text
Produto principal
Amazon
    │
    ├── comparação Mercado Livre → monitorada na nuvem
    └── comparação KaBuM          → monitorada na nuvem
```

## Histórico separado

Os preços das ofertas comparadas são gravados em:

```text
offer_history
```

Eles NÃO são misturados com:

```text
price_history
```

`price_history` continua representando o histórico do produto principal.

### Controle de volume

A V1.8.1 só insere uma nova linha em `offer_history` quando:

- ainda não existe histórico daquela oferta; ou
- o preço mudou desde a última captura.

Se o preço permanecer igual, o servidor verifica normalmente, mas não cria linhas repetidas desnecessárias.

## Banco necessário

Antes de usar esta versão, a tabela abaixo precisa existir no Supabase:

```sql
create table if not exists offer_history (
    id bigint generated by default as identity primary key,
    product_id text not null references products(id) on delete cascade,
    loja text not null,
    url text not null,
    preco numeric not null,
    captured_at timestamptz not null default now(),
    unique(product_id, loja, url, captured_at, preco)
);

create index if not exists idx_offer_history_product
on offer_history(product_id);

create index if not exists idx_offer_history_date
on offer_history(captured_at);

create index if not exists idx_offer_history_loja
on offer_history(loja);
```

## Teste 2 — disparo manual

No PowerShell:

```powershell
Invoke-RestMethod `
  -Method POST `
  -Uri "https://vigia-backend-cjwb.onrender.com/api/monitor/run" `
  -Headers @{
    "X-Vigia-Monitor-Secret" = "SEU_MONITOR_SECRET"
  }
```

A V1.8.1 retorna também:

```text
productsSelected
offersFound
offersSupported
offersChecked
offersSuccess
offersFailed
offersIgnoredUnsupported
historyInserted
```

No seu teste atual, com o produto Amazon contendo comparações de Mercado Livre e KaBuM, o objetivo é obter pelo menos:

```text
productsSelected : 1
offersFound      : 2
offersSupported  : 2
offersChecked    : 2
```

`offersSuccess` dependerá de cada loja aceitar a requisição server-side no momento do teste.
